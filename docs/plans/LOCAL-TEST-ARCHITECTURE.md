## 2. 当前 Key 登录与数据归属

1. 用户在工作流页面输入 Key；仅本地测试服务向 `http://127.0.0.1:18080/v1/usage` 验证。正式服务目前固定调用官方 HTTPS usage。
2. Bridge 在任务成功的结算阶段才需要用户 Key；它把 Key 以 AES-256-GCM 加密保存在本地账本，结算或释放后立即擦除。不写入任务状态或日志。浏览器使用 HttpOnly、SameSite=Strict Cookie，写请求另需 CSRF。正式服务不能直接采用此临时方案，需可信授权及受保护凭据设计。
3. 工作流 owner 是服务端持久 `identity-secret` 对 Key 计算的 HMAC；素材、草稿、任务和结果按 owner 存放。相同 Key 可恢复历史；换 Key 不会自动合并。历史是工作流服务本地文件，不是 sub2api 账号级历史。
4. 已签发会话不会随 Key 吊销立即失效，最长 30 分钟；服务进程重启清空会话。Toolbox 工具接入 Key 不参与工作流。

## 3. 当前任务与结果链路

1. 客户端通过工作流 WebView 选择模板、创建草稿、输入描述及参考图。模板和图由 Toolbox 服务管理，不信任任意节点、路径或外部命令。
2. 点击启动先获取本地测试报价，确认后提交草稿版本和签名报价；服务端创建任务并做余额预检与本地软预留。重复启动同一草稿返回同一任务。
3. 预留成功后 Toolbox 将图和参考图交给私有 ComfyUI；图片节点是参考图拼贴模拟，**不是 AI 生图**。只有明确成功后才按单位调用网关扣费；明确失败或取消不扣费。结果及任务仍按 Key owner 隔离。
4. 服务重启时进行中任务标记中断，不自动重放；提交、执行或计费结果不确定时保留待核对，不盲目结算。结算后会用 `model_stats` 核对次数，必要时补记。

## 4. 目标异步计费链路（未接入客户端）

```text
工作流 → 权威报价 → 用户确认 → Bridge 保存任务意图
       → sub2api 原子冻结用户钱包余额 → 可信执行器 → 任务终态
           成功 → 幂等结算 → 用户账单和结果
           明确失败 / 确认取消 → 幂等释放 → 失败记录
           状态未知 → 保留冻结，查询和对账，不自动重提
```

- sub2api 是唯一余额权威来源，Bridge 不维护第二钱包；一个任务不能同时走 sub2api 图片原生扣款和 Bridge 计费扣款。
- 当前已落地后付费版本：签名报价 → 余额预检/软预留 → 执行 → 成功后逐单位 `per_request` 扣费。旧的任务级冻结记录、事务事件与 Go fixture 已撤回。
- **尚未完成：**正式 Key 鉴权与分组/IP/配额/订阅规则；权威价格及价格变更事务一致性；多进程任务持久队列、执行结果证明和重启对账；缓存失效与用户可见账单；客户端和 Bridge 正式接线。
- 超时或断线不证明执行失败：上游可能仍运行或收费。必须核对任务，不能保证所有超时立即不产生费用。

## 5. 本地测试安全边界

所有测试端口绑定本机回环；数据库和 Redis 的测试容器不向宿主机映射端口。测试 EXE 配置独立应用标识、home/data，禁用正式更新安装；WebView 数据目录的隔离仍需桌面实测。测试副本不能用于生产或分发。

本地 HTTP Key 和测试凭据均仅供本机临时环境；不要将真实 Key 输入本地测试版或提交到仓库。测试执行结果与用户账务应始终标记模拟。未来分机部署/FRP 需要单独设计服务身份、加密、权限和恢复，目前未部署。
