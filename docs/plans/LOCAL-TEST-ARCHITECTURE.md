## 2. 当前 Key 登录与数据归属

1. 用户在工作流页面输入 Key；仅本地测试服务向 `http://127.0.0.1:18080/v1/usage` 验证。正式服务目前固定调用官方 HTTPS usage。
2. 本地计费测试副本校验后将测试 Key 临时保存在服务进程的 30 分钟会话内存中，以便冻结前重新鉴权；不写入工作流状态或日志。浏览器使用 HttpOnly、SameSite=Strict Cookie，写请求另需 CSRF。服务重启清除会话。正式服务不能直接采用此临时方案，需可信授权及受保护凭据设计。
3. 工作流 owner 是服务端持久 `identity-secret` 对 Key 计算的 HMAC；素材、草稿、任务和结果按 owner 存放。相同 Key 可恢复历史；换 Key 不会自动合并。历史是工作流服务本地文件，不是 sub2api 账号级历史。
4. 已签发会话不会随 Key 吊销立即失效，最长 30 分钟；服务进程重启清空会话。Toolbox 工具接入 Key 不参与工作流。

## 3. 当前任务与结果链路

1. 客户端通过工作流 WebView 选择模板、创建草稿、输入描述及参考图。模板和图由 Toolbox 服务管理，不信任任意节点、路径或外部命令。
2. 点击启动先获取本地测试报价，确认后提交草稿版本和签名报价；服务端创建任务并向 :18083 预留本地测试余额。重复启动同一草稿返回同一任务。
3. 预留成功后 Toolbox 将图和参考图交给私有 ComfyUI；图片节点是参考图拼贴模拟，**不是 AI 生图**。明确成功后结算测试余额并记本地流水；明确失败后释放冻结。结果及任务仍按 Key owner 隔离。
4. 服务重启时进行中任务标记中断，不自动重放；提交、执行或计费结果不确定时保留待核对，不盲目结算或释放。当前没有自动重启对账，可能需要人工核对冻结记录；关闭客户端不自动停止任务。

## 4. 目标异步计费链路（未接入客户端）

```text
工作流 → 权威报价 → 用户确认 → Bridge 保存任务意图
       → sub2api 原子冻结用户钱包余额 → 可信执行器 → 任务终态
           成功 → 幂等结算 → 用户账单和结果
           明确失败 / 确认取消 → 幂等释放 → 失败记录
           状态未知 → 保留冻结，查询和对账，不自动重提
```

- sub2api 是唯一余额权威来源，Bridge 不维护第二钱包；一个任务不能同时走 sub2api 图片原生扣款和 Bridge 终态扣款。
- 已有内部原型：任务级冻结记录、事务事件、重复操作防重、结算/释放互斥，测试签名报价及任务凭据。隔离 PostgreSQL 并发和 Mock 服务级测试已通过。
- **尚未完成：**正式 Key 鉴权与分组/IP/配额/订阅规则；权威价格及价格变更事务一致性；凭据安全持久化、续期、吊销；多进程任务持久队列、执行结果证明和重启对账；缓存失效与用户可见账单；客户端和 Bridge 正式接线。
- 超时或断线不证明执行失败：上游可能仍运行或收费。必须核对任务，不能保证所有超时立即释放或上游不产生费用。

## 5. 本地测试安全边界

所有测试端口绑定本机回环；数据库和 Redis 的测试容器不向宿主机映射端口。测试 EXE 配置独立应用标识、home/data，禁用正式更新安装；WebView 数据目录的隔离仍需桌面实测。测试副本不能用于生产或分发。

本地 HTTP Key 和测试凭据均仅供本机临时环境；不要将真实 Key 输入本地测试版或提交到仓库。测试执行结果与用户账务应始终标记模拟。未来分机部署/FRP 需要单独设计服务身份、加密、权限和恢复，目前未部署。
