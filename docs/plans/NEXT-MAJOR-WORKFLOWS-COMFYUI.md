# 下一大版本预研：基于 ComfyUI 的 CYAPI 工作流

> 历史方案归档：以下记录保留当时决策，不代表当前部署状态。工作流现已进入客户端主线，连接既有远程 Service；本机研究代码已删除。当前说明见 [工作流](../WORKFLOWS.md)。

更新日期：2026-10-27。状态：**预研中，不上线，不作为现有版本的功能承诺**。

## 1. 定位与本次决定

CYAPI 提供文本、图片、视频、语音等模型 API；工具箱把这些能力组织为可以重复使用的任务工作流。用户选择任务、提供材料、运行流程并获得成品，不需要安装 Codex、Claude Code 或 OpenCode。

- 同一个 App 内依次设「工具接入」「工作流」（Workflow）两个平级入口；工作流不从属于 Agent 或某个软件，不拆成第二个 App。
- 首个业务方向是图片生成，后续再扩展图片编辑、视频、语音等。
- 优先复用 **ComfyUI 的真实工作流引擎**，不另写一套节点调度器，也不只是模仿画布。
- **当前改为独立常驻服务：先在本机单用户测试，之后可另行迁移到服务器。** ComfyUI 只编排和轻量处理，不下载生图模型；当前模型接口仍为本机模拟。
- 普通用户使用「模板 + 参数表单 + 结果」，进阶用户可以查看或编辑同一条 ComfyUI 工作流。
- 允许在每一步后修改方案；验证不通过时先记录问题，不为了维持选型强行推进。
- **2026-10-26 顺序调整：先把第 3 步的模拟运行页接入独立客户端供反馈，再继续第 2 步真实 API。** 本机真实引擎不变，只用模拟接口；界面验收不等待付费测试授权。
- **2026-10-27 架构调整：** 为消除逐任务 / 逐画布冷启动，停止扩展旧表单＋检查副本主流程；一套独立常驻 ComfyUI 同时提供原生网页与执行，客户端仅连接网页。服务代码单独维护，本轮不部署服务器。
- **2026-10-27 产品调整：** 服务连接页不是用户首页。工作台以「工作流库 → 预览 → 草稿 → 显式启动 → 队列 → 结果 / 下载」为主线，原生画布用于预览 / 编辑，连接与日志收进设置。服务推荐来自版本化目录，个人工作流支持分享文件；公网推送仍待鉴权设计。
- **2026-10-27 导航试版：** 固定两个平级入口，下方侧栏随工作台变化；创作侧提供工作流库 / 草稿 / 任务队列 / 结果，不显示 Agent 选择器，也不在纯创作启动时加载工具目录与 Agent 路由。工具侧保留模型接入 / 集成 / Skill / MCP / 环境 / 用量 / 日志，选择器改称「当前工具」。记住上次工作台和两侧页面，不新增选择首页；正式版保持原导航。

### 本轮双工作台导航实现

- 创作 iframe 首次打开后驻留；切换到工具或全局设置只隐藏，不销毁，保留编辑页、上传和画布状态。关闭 App 不保证保留未保存输入；草稿自动保存、离开创作页前等待保存，画布仍需显式保存。
- 画布不再叠加底部说明条，「保存画布」及载图 / 保存状态迁入弹窗标题栏；保存通道只接受精确同源父子 frame 的保存 / 状态消息，不转发到桌面。弹窗使用 flex 填充而非固定标题高度，打开时锁背景滚动，普通说明只滚动正文；受管理画布隐藏全局多工作流页签，保留画布缩放 / 拖动及必要列表滚动。
- 桌面内隐藏服务自身的四个页签，改由 App 创作侧栏控制；独立浏览器入口仍保留页签。
- 仅增加受限 UI 消息通道：精确校验双方 origin 和窗口 source，只允许四个页面名、浅 / 深外观、当前页与锁定布尔值。不接收路径、任意 URL、图、素材、凭据或原生命令，不转发 IPC，不增加 capability 或放宽 CSP。
- 上传 / 业务操作 / 画布或对话框打开时锁住创作页导航；仍可切换工作台且上传继续。保存失败不跳页，保留输入重试；页面内的跳转会同步侧栏。
- 共享外观、应用更新和帮助；工作流设置仍在服务内，工具配置 / Skill / MCP 与创作模板 / 素材 / 草稿 / 任务独立。创作外观不跟随所选 Agent 配色。

### 待确认：工作流身份与付费入口（尚未实现）

- 当前仅本机模拟，没有工作流 API Key 配置入口，也没有账号登录；工具侧填写的 Key 不会自动提供给工作流。已有本机历史不需要登录，不是云端账号历史。
- 建议在工作流右上角增加独立「连接 CYAPI / API Key」入口，配置工作流专用 Key；若 CYAPI 提供账号授权协议，再接入账号登录。API Key 鉴权不能冒充账号登录或自动提供云端历史。
- 凭据只交给可信执行服务，采用受保护的凭据存储，不进图、分享文件、浏览器 localStorage 或日志；本机与未来远端托管的凭据方案需分别设计，不读取 Agent 配置。
- 跨设备历史必须有稳定用户身份和服务端归属 / 访问控制，不按本机文件或明文 Key 当用户数据库；Key 更换 / 吊销后任务和历史如何归属需明确。
- 余额 / 实际费用 / 账户信息依据已核对接口，不根据验证请求成功伪造余额或「已登录」。浏览与编辑可先开放，真实付费启动必须具备有效凭据、明确费用提示和用户确认；模拟模式继续明确不计费。
- 此节只是产品建议，真实 API 协议、账号接口、模型和付费预算仍需确认；本轮不实现虚假登录、收集真实 Key 或测试付费调用。

## 3. 暂定技术结构

```text
工具箱（React + Tauri）
  内嵌服务工作台（研究版仅精确允许本机 8188，无服务 IPC）
               │ 受限 iframe → HTTP（也可直接用浏览器）
               ▼
独立常驻测试服务（本机回环地址，固定版本）
  工作流库 / 草稿 / 队列 / 结果，原生 ComfyUI 画布与引擎
               │ 本机模拟 HTTP（未来另行授权 HTTPS）
               ▼
CYAPI 模型 API（当前阶段替换为本机模拟服务，不产生模型费用）
```

职责划分：

| 层             | 职责                                              | 不做什么                                         |
| -------------- | ------------------------------------------------- | ------------------------------------------------ |
| 工具箱（当前） | 内嵌服务工作台、健康检查、连接设置                | 不启动 / 停止引擎，不重新实现画布和调度          |
| 独立服务       | 模板、草稿、任务 / 产物持久化、常驻引擎、原生画布 | 不依赖桌面 stdio 生命周期，不宣称生产多用户      |
| ComfyUI        | 节点连线、依赖执行、缓存和执行事件                | 不默认安装本地推理模型                           |
| CYAPI 节点包   | 协议适配、请求、任务 ID、结果转换、调用状态       | 不使用 Comfy 账户和付费 Partner Nodes 代替 CYAPI |
| 模板声明       | 标题、封面、输入参数映射、最终输出、版本依赖      | 不发明替代 ComfyUI 的执行图格式                  |

使用 ComfyUI 原生 API 图作为权威输入，通过原生编辑器载入；当前仅额外保存原生节点布局，避免序列化 widget 副本覆盖表单或泄漏任务素材。模板声明增加展示信息与输入要求；当前表单明确只支持一个模拟图片源。引擎和节点包固定版本，不跟随 `latest` 自动升级。

## 4. 六个落地步骤

每一步交付后更新本文及实验记录，给出「已验证 / 未验证 / 阻塞」，再决定是否进入下一步。模拟通过不能标记为真实 CYAPI 调用通过；Windows 验证不能代表 macOS 已验收。

### 第 1 步：本机引擎可行性验证（Windows 模拟链路已通过）

**目标：** 不接正式客户端、不花模型费用，确认真实 ComfyUI 能否作为纯 API 管线引擎。

- 在仓库忽略的 `output/workflow-research/` 中建立独立 Python 环境和固定 ComfyUI 源码。
- 使用 CPU 模式，仅监听 `127.0.0.1`，关闭自动打开浏览器，不启用 Manager 和官方付费节点。
- 只加载自有实验节点；用本机模拟图片 API 验证「参数 → HTTP 节点 → IMAGE → 保存 → 取回文件」。
- 从独立客户端通过 API 提交图、监听执行消息并核对最终历史，不依赖 ComfyUI 画布的交互回调。
- 验证相同输入的缓存行为、显式再次生成、错误返回、引擎退出、测试数据不含 Key。
- 记录 Python / ComfyUI / Torch 版本、安装体积、冷启动耗时、内存和测试覆盖；启动后主动结束自建进程。

**交付：** 可复跑的实验脚本、自有实验节点、模拟 API、验证报告。完整源码和依赖留在忽略目录，不复制进客户端发布物。

**通过条件：** CPU 模式能启动，真实引擎完成模拟 HTTP 图片工作流，输出图片可取回，失败可识别，没有调用外网模型或改写现有 Python / ComfyUI / Agent 配置。

**决策点：** 根据依赖体积、冷启动、兼容性，决定本地引擎是否继续。此步不承诺一键安装、持久恢复和多用户安全。

**2026-10-26 结果：** Windows + ComfyUI `v0.42.0` + CPU Torch 的完整模拟链路连续两次通过，每次 13 项检查；没有调用真实 CYAPI 或下载本地模型。首次启动约 60 秒，随后两次全新进程启动约 6.7 / 7.7 秒；完整依赖环境约 1.75 GiB，引擎进程树采样 RSS 峰值约 492–499 MiB。详见[实验结果与边界](../../research/comfyui-local/RESULTS.md)和[重跑说明](../../research/comfyui-local/README.md)。保留方案 A；按用户新反馈先做独立模拟客户端，真实协议核对与付费授权仍单独推进。

### 第 2 步：一条真实 CYAPI 图片链路

**目标：** 从模拟服务换成一项明确支持的 CYAPI 图片接口。

- 先核对实际接口协议、模型 ID、输入参数、返回图片形式与计费方式，不根据模型名猜能力。
- 用户确认测试模型与付费调用预算后，才执行少量真实请求；不从现有 Agent 配置中自动读取 Key。
- 实现图片节点适配，优先跑通一个接口；兼容接口也要明确支持范围，不声称所有模型可替换。
- 凭据从引擎侧受限配置或进程上下文获取，只在图中引用配置标识；不要把 Key 放进节点参数、命令行、日志、导出 JSON 或 PNG 元数据。
- 对超时、鉴权失败、余额不足、限流、无效图片和状态未知给出不同结果。
- 确认节点包许可与分发边界，再确定后续打包方式。

**交付：** CYAPI 图片节点最小实现、一条真实成图记录、已核对的协议与错误说明。

**通过条件：** 明确授权的一次真实调用得到有效图片；重复点击和超时不会静默自动发起第二次付费提交。

**决策点：** 确定首批支持的图片协议与模型，是否需要图片编辑；仍不扩展视频。

### 第 3 步：客户端最小运行页（模拟体验提前进行）

**目标：** 不打开节点编辑器，用户也能使用图片工作流。

- 加入独立于 Agent 的预研「工作流」入口，显示预研状态。
- 先做一条模板：填写提示词、选择已验证模型与参数、运行、查看节点状态、预览和保存图片。
- 通过独立 Rust 服务访问本机引擎，长任务不能占用现有安装 / 配置全局锁。
- 前端保留当前 CSP 原则，不为了连本机服务直接放开任意网络、脚本或 iframe 权限。
- 显示未准备、未启动、运行中、失败、状态未知等真实状态；网页模式不能伪装已经执行成功。
- 最小运行记录包含模板版本、输入、模型、状态、输出位置和错误，不包含凭据。
- 当前子阶段只提供模拟节点；产品模板接收参考图与描述，输出明确标记的参考图拼贴。正常 / 503 / 坏图 / 超时仍可在节点内测试。
- React / Rust 只连接工作台，不启动 Python。服务模板 / 任务画布只读；个人模板 / 未启动草稿画布可保存编辑；受管理图返回工作台显式启动。
- 旧实验文件不混入新历史。新服务 JSON 保存草稿、提交意图、任务状态与结果；重复启动同一草稿复用任务。服务重启将活跃任务标记中断，不重放；尚非生产级持久事务队列。

**分阶段交付：** 先交付真实引擎 + 模拟图片 API 的独立桌面体验版（[使用说明](../../research/comfyui-local/CLIENT.md)）；真实 CYAPI 成图闭环仍以第 2 步授权和协议验证为前提。

**通过条件：** 不依赖 Codex 等 Agent；从表单到成图完成闭环，切换页面不丢任务，原有配置与安装功能无回归。

### 第 4 步：组合工作流与编辑体验

**目标：** 验证工作流的组合价值，而不只是给图片 API 加表单。

- 增加「用户想法 → 文本模型整理提示词 → 图片模型 → 成图」模板。
- 首版将人工确认实现为两个明确阶段：先生成提示词，用户确认后再提交生图，不假设 ComfyUI 有现成的持久人工暂停能力。
- 增加薄模板声明、输入参数与节点字段映射，并保留编辑图 / API 图的同步验证。
- 先通过独立窗口或浏览器打开原生 ComfyUI 编辑器；不直接把 GPL 前端代码合入当前 React 包。
- 修改后另存用户副本，官方模板版本更新不覆盖用户改动。

**交付：** 基础文生图与组合生图两条模板、简单运行和原生画布的切换实验。

**通过条件：** 同一模板能用表单运行，也能在画布中理解和修改；人工确认之前没有付费生图。

**决策点：** 根据实际易用性，再决定是否嵌入画布、增加参考图或开放更多节点。

### 第 5 步：可靠性、隐私与运行环境管理

**目标：** 将「可以跑」提升到可持续使用的预研版本。

- 引擎独立准备、显式启动后常驻：固定依赖、独立目录，不改变系统 PATH / Python，不接管用户已有 ComfyUI。当前不自动安装或重启，生产哈希锁与监管仍待补。
- 进程身份、端口冲突、健康检查、关闭行为、日志上限、崩溃后恢复和残留进程处理。
- 只信任自有受审节点；不启用在线任意安装自定义节点。不把任意工作流 JSON 当作安全沙箱。
- 本机服务增加访问保护；仅监听回环地址不是完整的鉴权。网页、恶意本地进程和文件接口都要评估。
- 持久化调用记录与上游任务 ID，区分缓存复用、明确重新生成、重试下载、继续查询；状态未知时不自动重新付费。
- 正确表达取消：本地停止不等于上游取消，也不承诺退款。ComfyUI 内存缓存不等于防重复计费或持久恢复。
- 输入 / 结果大小限制、下载地址校验、路径约束、密钥与元数据排查、导出脱敏。

**交付：** 运行环境管理、持久任务 / 产物记录、失败恢复与安全测试、独立的预研应用标识和数据目录。

**通过条件：** 断网、超时、重复提交、重启和取消的行为可解释且可验证；不污染现有正式版数据。

### 第 6 步：扩展评估与下一版本决策

**目标：** 决定是否进入正式大版本研发，而不是自动发布。

- 补 Windows / macOS 对应实机验收和安装体积、启动、内存对比。
- 根据已验证协议，选择图片编辑或图片生成视频中的一个扩展，避免同时铺开全部模型类型。
- 评估异步视频、资产大小、并发和跨步骤恢复是否适合 ComfyUI。
- 总结许可、分发、升级兼容、任务安全和用户体验；列出继续使用、本地优化或改成其他引擎的依据。
- 用户确认后，另定版本号、合并方案、发布清单、线上接口与灰度计划；本文不授权上述动作。

**交付：** 下一大版本 Go / No-Go 记录及调整后的正式研发计划。

### 2026-10-27：补原生画布以核对实际图

- **依据：** 用户无法从表单和结果判断构建了什么图、用了哪些节点；状态卡片不能替代真实画布。
- **调整：** 在客户端独立 Tauri WebView 打开本机 ComfyUI 原生前端，通过自有节点扩展自动载入选中任务保存的 API 图；运行前可查看当前表单草稿。两个节点为 `CYAPIResearchMockImage` → `SaveImage`，提示词是图片节点输入，本机引擎不是节点。
- **边界：** 画布为检查副本，编辑不回写，前后端均禁止画布提交；暂不宣称同一图双向编辑已完成。缺少历史图明确失败，不用新模板补造执行快照。
- **生命周期：** 每个客户端一个运行任务、一个独立画布会话；画布按需启动，关闭窗口 / 主客户端释放，运行任务仍按结束即释放。独立引擎避免画布编辑或关闭影响客户端任务。
- **隔离：** 不修改 ComfyUI 核心、不复制第三方前端源码进入 React / EXE；启用上游 offline CSP，原生画布不授予客户端 IPC 权限。仍不涉及真实 API、模型下载或正式发布。
- **验收：** 真实桌面载图、图与执行快照一致性、执行隔离和退出清理的结果见 [RESULTS.md](../../research/comfyui-local/RESULTS.md)。

- **依据：** 用户明确指出反复启动慢，要求先做独立本机测试服务，之后自行部署服务器。
- **调整：** 新建自包含 `research/workflow-service/`，使用真实原生前端与执行引擎；管理进程不导入 Torch，不再随任务或画布窗口启动引擎。客户端仅健康检查并打开固定网页，关闭窗口不停止任务或服务。
- **运行：** 提供独立 Python `start / serve / status / stop`；本仓库 npm 只是快捷入口。固定回环 URL、OS 数据目录实例锁、合成令牌保护停止接口，按实例清理进程树。

- **边界：** 本轮仅回环单用户模拟，不读取旧 Key、真实调用、模型下载或服务器部署。公网代理、鉴权、文件 / 队列隔离、任务库与 GPL 审查仍是迁移前置事项。
