# Agent 日志分析与工具箱日志

Codex、Claude Code 和 OpenCode 分别按软件自身的数据结构在本机只读分析，不发送给模型或目录服务器。侧栏选择对应工作区，打开「日志」即可查看。下面先介绍 Codex，再说明 Claude Code / OpenCode 的专用解析和统计口径。

## 使用

1. **概览**：分别显示模型 HTTP 尝试、HTTP 失败、重试、回合错误和关联会话，并提供故障线索及实际请求地址。
2. **会话分析**：按标题、项目、模型搜索会话，打开后合并该会话的运行日志和 JSONL 回合、工具记录；显示已记录的累计 token 快照。归档的 `.jsonl.zst` 也可直接解析。
3. **模型请求**：按失败、来源、会话和关键词筛选。每条记录保留 URL、状态及 `x-request-id`，用于对照上游日志。
4. **故障归类**：按认证、限流、上游服务、网络、响应流、MCP、工具权限、桌面和后台功能等特征归组。计数为证据条数，同一次故障可能产生多条记录；建议不等同于已确认原因。
5. **全部事件**：在同一个分析快照内筛选、分页加载。点击「证据」查看来源文件、SQLite row 或文本字节偏移、脱敏正文与跨度上下文；同一毫秒内按原记录顺序显示。
6. **数据来源**：查看实际读取的文件、WAL 大小、缺失或不兼容来源，以及各来源的截取上限。
7. **自动更新**：每 15 秒建立新快照；默认关闭。手动刷新与自动刷新使用相同的解析流程。
8. **导出报告**：保存当前快照及最多 2,000 条事件摘要至工具箱数据目录 `reports/codex-analysis-*.json`；在会话页导出时还包含该会话分析。显示和导出前脱敏，导出另隐藏用户主目录。

## Codex 数据来源

| 来源 | 作用 | 读取方式 |
| --- | --- | --- |
| `logs_<n>.sqlite` | HTTP 请求、重试、回合错误与运行事件 | 按版本选择可读数据库，只读查询并包含 WAL；最多最近 20,000 条非 TRACE 记录 |
| `state_<n>.sqlite` | 会话标题、项目、模型、provider、归档状态及 rollout 路径 | 兼容可选列缺失；最多最近 500 个时间窗内会话 |
| CLI / 桌面文本日志 | tracing 事件、桌面进程与连接告警 | 发现多层日期目录；最多最近 24 份文件，每份尾部 512 KB |
| `sessions/`、`archived_sessions/` | 回合生命周期、工具调用与累计用量 | 按需解析 `.jsonl` / `.jsonl.zst`；不读取聊天正文、工具参数或输出 |

- 尊重 `CODEX_HOME`、`config.toml` 的 `sqlite_home` / `log_dir`，并发现 Windows 常规及 Store 应用日志候选目录。
- SQLite 缺失时仍读取文本；会话数据库不可用时，从会话文件的 `session_meta` 恢复列表。旧数据库列缺失不导致标题和 provider 一并丢失。
- SQLite 与 CLI 中时间、模块、级别、线程和正文完全相同的记录合并，保留两份来源位置。其他相近记录不推测为同一次请求。
- Windows 常规与 Store 虚拟目录指向同一文件时只读取一次；会话数据库中的 `\\?\` 路径也可正确关联。
- 模型请求只认实际模型接口 HTTP 记录。`Request completed` 只表示收到响应；401、403、429、5xx 均算 HTTP 失败。HTTP 成功不表示回合完成。
- token 取最后一条累计快照，不把重复 `token_count` 相加。缓存输入已包含在输入中，推理输出已包含在输出中；累计值不等于所选时间窗新增消耗。
- 普通会话文件最多解析尾部 32 MB；压缩会话最多解压读取前 32 MB，超限时明确提示最新事件可能未读取。会话时间线最多展示最近 1,000 条；截断、异常行和缺失来源均在页面标出。
- 总事件最多保留最新 20,000 条；「全部」表示不限制时间起点，仍受文件和记录上限约束。查询不根据文件修改时间补造事件时间。

## Claude Code 与 OpenCode 日志

两个工作区均提供「概览、会话分析、模型响应、故障归类、全部事件、数据来源」。支持时间范围、会话/来源/事件类型/级别/失败筛选、同一快照分页、默认关闭的每 15 秒自动刷新、结构证据和脱敏报告导出。会话页提供父会话、子代理与分叉来源跳转；缺少父记录时明确提示，不猜测关联。

| 软件 | 主要来源 | 专用处理 |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/**/*.jsonl`、`sessions-index.json`、`debug/*.txt` / `*.log` | 合并相同 `message.id` 的流式片段；按 `tool_use.id` / `tool_use_id` 关联调用和返回；主会话与 `subagents` 独立计数；识别 API 错误、重试和上下文压缩 |
| OpenCode | `~/.local/share/opencode/opencode.db` 和 `log/` | 兼容新版 `session_v2 / session_message` 与旧版 `session / message / part`；包括 WAL 中的记录；解析内嵌工具、压缩、响应错误及 logfmt 运行日志 |
| OpenCode 旧存储 | `storage/session`、`storage/message`、`storage/part` 的 JSON | 仅在数据库缺失或不兼容/读取失败时回退，避免迁移后的两份数据重复计算 |

- Claude 目录尊重 `CLAUDE_CONFIG_DIR`；OpenCode 数据目录尊重 `XDG_DATA_HOME`，与 `XDG_CONFIG_HOME` / `OPENCODE_CONFIG` 指向的配置目录分别处理。
- **模型响应数是观测到的响应消息数**，不会推算实际 HTTP 请求次数。Claude 的合成 API 错误另列，不计模型响应；OpenCode 运行日志中的 HTTP 可能是本地服务器请求，另列为「运行日志 HTTP」。
- 用量是时间窗内已读取、去重消息的合计。Claude 输入 = 未缓存输入 + 缓存读取 + 缓存创建；OpenCode 输入 = input + cache.read + cache.write，输出 = output + reasoning。子项已含在总量；step-finish 重复用量不相加；压缩记录有独立用量时计入合计。
- 会话统计只覆盖该会话；子代理独立显示。没有完成字段时显示「未记录完成状态」，不据此判断任务仍在运行。故障分组提供排查线索，不把工具失败或重试判定成整个会话失败。
- 证据只保留消息/调用 ID、模型、状态、耗时、错误类型和用量；可定位到文件字节偏移或 SQLite 表主键。不返回聊天正文、隐藏推理、工具参数、输出或原始运行日志整行。会话标题与项目目录仍显示。
- Claude 最多读取最近 200 个会话文件，每份尾部 8 MB；单条 JSON/JSONL 上限 2 MB，JSON 读取预算 64 MB。OpenCode 数据库消息/part 每表最多 20,000 行、会话元数据最多 5,000 行；旧 JSON 回退最多 50 份会话元数据、100 份消息及 50 份工具文件。
- 运行文本最多最近 12 份，每份尾部 512 KB，单行最多 64 KB。目录扫描最多 5 层、20,000 项，跳过链接。最终最多保留 20,000 个结构事件；会话时间线最多 1,000 条，每页 200 条，报告最多导出 2,000 条结构事件。
- 「全部」仍受上述上限约束。损坏、过大、无时间、截取及不兼容来源在页面中提示；缺少日志或未启用 Claude debug 时明确显示未发现，不生成示例记录。报告写入工具箱数据目录的 `reports/claude-analysis-*.json` / `reports/opencode-analysis-*.json`，导出另隐藏用户主目录。

实现和验证见 [Claude Code / OpenCode 专用日志分析](../docs/plans/CLAUDE-OPENCODE-LOG-ANALYSIS.md)。

## 工具箱日志窗口

侧栏底部「日志窗口」可以随时打开；窗口已打开时再次点击该按钮即可关闭，点击窗口以外的任意位置也会关闭，按 Esc 同样有效。安装弹窗另有「查看本次日志」，用户发起的操作失败时会自动打开对应操作的日志；启动时的后台读取（状态、预览、更新检查等）失败只写入日志，不自动弹窗。

支持级别/关键词/操作筛选、展开上下文、复制、暂停跟随、导出和打开日志目录。「清空视图」只移除本次窗口已显示的行，不删除文件日志。

记录启动、目录请求、离线包校验、运行环境准备、暂存写入、目录提交、安装记录、卸载、配置及接入操作的开始、完成或失败。日志查询独立于安装服务锁，长时间下载和安装时仍可查看。

文件日志默认在 `%LOCALAPPDATA%\CYAPI-toolbox\data\logs\`；设置 `CYAPI_TOOLBOX_DATA_DIR` 时位于该目录的 `logs/`。主位置不可写则尝试当前用户临时目录，全部失败仍保留当前会话的内存日志并显示提示。安装服务初始化失败时，窗口仍可以使用排查和日志功能。

单文件约 2 MB，最多 20 个文件/40 MB/7 天，按上限清理最旧文件；多个实例使用独立文件。内存上限 5,000 条，窗口显示最近 1,500 条；落盘队列满或历史过期时会提示记录可能不完整。工具箱日志窗口导出的报告最多保留最近 20 份。进程突然退出时，尚未写出的队列可能丢失。

## 检测范围

- 目录写入结果属于 Windows 本机的当前工具箱进程，不代表 Codex 沙盒、WSL、远程或云端任务具有相同权限。
- 配置对照仅使用当前全局配置，不完整计算项目、profile、会话覆盖或 ChatGPT 登录路由。地址不同表示观察差异，不直接判定配置错误。
- 运行 SQLite 依赖 Codex 仍输出相关 target；某个来源缺失、被占用或结构不兼容时，显示来源错误并继续读取其他来源。
- 自动发现只扫描 Codex 候选目录，最深 4 层、每个根目录最多 20,000 项；不跟随符号链接或目录联接。未知日志位置不会自动遍历整个用户目录。
- 测试只清理本次创建的随机目录，不覆盖真实配置，不自动创建缺失的目标目录，不修改 ACL、审批或沙盒策略。拒绝网络/设备路径及目录联接/符号链接。
- 日志数据库只做只读查询，不会写入、压缩或修改 WAL；查询失败会提示数据库被占用，可稍后重试。
- 本版日志覆盖工具箱启动后的操作；工具箱 EXE 安装器、WebView2 引导和远程目录服务器内部日志尚未接入。
- 常见凭据在显示和落盘前脱敏，导出时再隐藏用户主目录。未知格式的自由文本可能包含其他敏感内容，分享前检查导出文件。

实现说明见 [Codex 专用日志分析](../docs/plans/CODEX-LOG-ANALYSIS.md)。
